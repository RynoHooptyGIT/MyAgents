# bmad v6.10.0 — Plan E: Party-Mode Overhaul

> **STATUS: LANDED** (2026-08-23) — artifact-verified. Shipped `team/core-skills/bmad-party-mode/`. See `docs/sync-notes-v6.10.0.md`.

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port bmad's overhauled party-mode: anti-consensus club (structured disagreement mode), persistent per-party memory, and point-to-point agent-team sync (replacing the shared-room model that leaked state between parties).

**Architecture:** The fork already has `team/workflows/party-mode/` with `workflow.md` and a `steps/` directory. Bmad's new party-mode lives at `src/core-skills/bmad-party-mode/` with SKILL.md, customize.toml, and five reference files. Port the bmad skill under `team/core-skills/bmad-party-mode/` and leave the existing `team/workflows/party-mode/` intact — the two coexist during the transition. A follow-up decision (not this plan) chooses which becomes canonical. Python script (`resolve_party.py`) is NOT ported, per the Plan A precedent.

**Tech Stack:** Markdown, TOML. No Python.

**Upstream refs ported:**
- `74e8f612` add anti-consensus club (#2530)
- `b0b17962` persistent per-party memory (#2484)
- `b119a35a` correct agent-team sync to point-to-point (#2539)
- `3dd88943` keep the party interactive and the room in sync (#2531)

**Out of scope:** Deletion of the existing `team/workflows/party-mode/` (kept in parallel), `resolve_party.py`, i18n docs.

**Depends on:** Plan B (`team/core-skills/` root exists).
