## Task 2: Make review layers configurable per project

The `customize.toml` schema already supports `[[workflow.review_layers]]` — that is what Plan A ported. What's new in #2550 is a merge convention: a project can add a `[[workflow.review_layers]]` block in its own `_bmad/custom/<skill>.toml` override, and it appends to (or replaces by `id`) the vendored list. The fork does not carry `_bmad/custom/`, so the equivalent needs to live somewhere.

**Files:**
- Create: `team/custom/` (fork's equivalent of `_bmad/custom/`)
- Create: `team/custom/README.md`
- Create: `team/custom/quick-dev.example.toml` — copy-and-edit template
- Create: `team/custom/dev-auto.example.toml`
- Create: `docs/review-layers.md` — how to override

- [ ] **Step 1: Create the custom overrides directory**

```bash
mkdir -p team/custom
cat > team/custom/README.md <<'EOF'
# Project-level skill customizations

Files in this directory override the defaults from vendored skills. Each
file is named `<skill-name>.toml` and merges into the corresponding
`team/workflows/*/*/customize.toml` or `team/core-skills/*/customize.toml`
using bmad's merge rules:

- Strings replace.
- Lists append.
- Tables merge key-by-key.
- Arrays of tables merge by `id`; matching `id` replaces, new `id` appends.

`*.example.toml` files are copy-and-edit templates — the loader ignores them.
EOF
```

- [ ] **Step 2: Add example overrides**

`team/custom/quick-dev.example.toml`:

```toml
# Copy to team/custom/quick-dev.toml and edit to override defaults.

# Replace an existing review layer (matching id):
# [[workflow.review_layers]]
# id = "edge-case-hunter"
# instruction = "…custom prompt or subagent recipe…"

# Append a new review layer (novel id):
# [[workflow.review_layers]]
# id = "compliance-check"
# name = "Compliance Check"
# instruction = "…"

# Disable a layer by setting instruction = "" for its id.
```

Copy the same content to `team/custom/dev-auto.example.toml` with the header comment adjusted.

- [ ] **Step 3: Document override behavior**

Create `docs/review-layers.md`:

```markdown
# Review Layers

Every implementation workflow (`quick-dev`, `dev-auto`) runs a review pass with
one or more layers. Each layer is an independent context-free reviewer with
its own prompt. Layers are defined in each workflow's `customize.toml` and can
be overridden per project.

## Default layers

Three layers ship as defaults:

1. **blind-hunter** — adversarial correctness (`bmad-review/references/lens-adversarial.md`)
2. **edge-case-hunter** — edge-case sweep (`bmad-review/references/lens-edge-case-hunter.md`)
3. **verification-gap** — behavior-coverage gaps (`bmad-review/references/lens-verification-gap.md`)

## Overriding

Create `team/custom/<workflow>.toml` (e.g. `team/custom/quick-dev.toml`).
Use `[[workflow.review_layers]]` blocks. Merge rules:

- Matching `id` → the block replaces the vendored one.
- New `id` → the block appends to the vendored list.
- `instruction = ""` → disables that layer.

Templates: `team/custom/quick-dev.example.toml`,
`team/custom/dev-auto.example.toml`.

## Reviewer independence

Every layer runs in a fresh context-free subagent. Do not have one layer read
or reference another's output. Layers converge only in the final triage step,
where their findings are compared and duplicates collapsed.

## Verification-gap focus

The verification-gap reviewer looks for **behavior** the tests do not cover,
not raw line coverage. Deterministic test-only coverage (unit tests exercising
private helpers) is preserved and not flagged as a gap.
```
