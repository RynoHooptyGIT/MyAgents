# bmad v6.10.0 — Plan A: Phase-4 Implementation Loop Port

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port bmad's promoted Phase-4 implementation loop (`bmad-quick-dev`) and its supporting `bmad-dev-auto` variant into the fork so the impl workflow matches upstream's canonical loop, with deterministic implementation handoff, three-layer review, and the `stories.yaml` contract with `bmad-spec`.

**Architecture:** Static-content port (matches investigate-skill precedent from `f503802c`). Bmad's `render.py` template renderer is NOT ported — it depends on bmad's `_bmad/config.toml` infrastructure the fork does not carry. Instead, the step files, review prompts, `customize.toml`, and `SKILL.md` are copied verbatim (or with minimal path adaptation) into `team/workflows/implementation/quick-dev/` and `team/workflows/implementation/dev-auto/`. Fork's existing `create-story` and `dev-story` workflows are left in place — Plan H removes them.

**Tech Stack:** Markdown (skill/step files), TOML (customize), XML (fork engine hooks). No Python renderer.

**Upstream refs ported:**
- `116d52f5` promote quick-dev to canonical Phase 4 loop (#2637)
- `52e4c634` stories.yaml contract between bmad-spec and bmad-dev-auto (#2549)
- `7376a4a0` minimal handoff, drop Code Map nudge (#2635)
- `83f81c81` nail down implementation handoff (#2629)
- `56a081fc` deterministic implementation handoff (#2561)
- `029ba287` docs: Quick Dev canonical implementation workflow (#2643)
- `e7af627e` deprecate create-story and dev-story (#2641) — read-only reference; deletion happens in Plan H

**Out of scope:** `render.py`, `_bmad/` config infra, i18n docs (`docs/cs/`, `docs/fr/`, `docs/vi-vn/`, `docs/zh-cn/`), test files under bmad's `test/` (they exercise the renderer we are not porting).
